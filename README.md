# Awesome Embodied Agents [![Awesome](https://awesome.re/badge.svg)](https://awesome.re)

> A curated, annotated list of agents that act in the physical world, with an emphasis on coding agents and LLMs as robot policies ("agent as a policy"): the harnesses that connect them to robots, the models and world models they run on, the benchmarks that score them, and the simulators, assets, perception tools and datasets underneath.

Maintained by [**BenchFlow**](https://benchflow.ai) · Join our [**Discord**](https://discord.gg/mZ9Rc8q8W3) · Sister list: [**Awesome Agent Evals**](https://github.com/benchflow-ai/awesome-evals)

Most lists in this area are link dumps. This one follows the rules of Awesome Agent Evals: every entry says what the thing is and why it belongs, URLs are checked, numbers are quoted verbatim from the linked source, dates are given, and dead projects are pruned or flagged. Robot results add two questions a reader needs answered: who judged success (the simulator's state, a held-out checker, a human, or the agent itself) and how many trials ran. Licences that restrict use are flagged too, because robot work often inherits non-commercial scenes, assets and weights.

"Agent as a policy" here means the agent decides what the robot does next, by calling robot tools, writing and running control code, or calling a learned controller, and is scored on what happens in the world rather than on a plan written in text.

**208 annotated entries, plus a starter set and a map of companies; every URL was checked on 2026-10-21.** Markers: 🆕 = released, or given a major new version, in 2025–2026 · ⚠️ = caveat. **Disclosure:** BenchFlow maintains this list and builds [Robo Use](#1a--harnesses-and-robot-operating-systems), which is listed and held to the same bar. Contributions welcome, see [CONTRIBUTING](CONTRIBUTING.md); a [daily scan](SCAN.md) proposes additions as pull requests that a maintainer must approve.

## ⭐ Start here

1. **[Robot-Use Agents](https://web.mit.edu/phillipi/www/writing/robot-use-agents.html)** — Phillip Isola (MIT) · *essay, 2026-09-07* — The case for general-purpose agents that use robots the way computer-use agents use computers: "Think of it as Claude acting as the puppeteer of a robot body."
2. **[Code as Policies](https://arxiv.org/abs/2209.07753)** — Liang et al. (Google) · *paper, 2022-09-16* — Language models writing robot policy code over perception and control APIs: the idea most coding-agent harnesses below build on.
3. **[Claude plays robotics](https://www.anthropic.com/research/claude-plays-robotics)** — Anthropic · *study, 2026-07-09* — Twelve models at four levels of control, from raw actions to supervising RL. Direct control mostly fails, which is why harness design matters.
4. **[CaP-X](https://capgym.github.io/)** — NVIDIA, UC Berkeley, Stanford, CMU · *benchmark, 2026-03-23* — The code-as-policy benchmark for coding agents in manipulation, with a training recipe on top.
5. **[Gemini 4 Argon for Robotics](https://developers.googleblog.com/gemini-4-argon-for-robotics/)** — Google · *blog + API, 2026-10-13* — A frontier model used as a robot agent end to end: self-improvement on a real arm, a simulated twin from one photo, and a curriculum that fine-tunes a VLA.
6. **[Can Jev Nav?](https://research.dimensional.org/system-one-navigation/)** — Dimensional · *benchmark, 2026* — Real-time navigation scored by SPL and cost per run, comparing coding agents, a typed "System One" model and a skill-level agent.
7. **[An Unexpected Robot Policy](https://arxiv.org/abs/2609.24170)** — RoboProbe and RoboDojo teams · *paper, 2026-09-21* — A frontier LLM ranked above every public policy on RoboDojo in simulation, and a real-robot test halted for unsafe actions.
8. **[Refuses in Chat, Complies with Arms](https://arxiv.org/abs/2610.14043)** — Robocurve and UCLA · *paper, 2026-10-03* — Why text-only safety evaluations do not transfer: refusal drops once the model controls a robot.

## 1 · Robot harnesses for coding agents

Software that connects a coding agent (Claude Code, Codex and others) or another LLM agent to a robot or a simulator: what the agent sees, which actions it may call, and who checks the result.

### 1a · Harnesses and robot operating systems

- **[Robo Use](https://robouse.ai)** — BenchFlow — <https://robouse.ai> · code <https://github.com/benchflow-ai/robouse> · PyPI <https://pypi.org/project/robouse/> · docs <https://robouse.ai/docs/> · suites <https://robouse.ai/docs/suites/> · *harness + benchmark, 0.6.0 2026-10-21* — "Agent as a policy for embodied agents": it turns robot benchmarks into tasks that a harness such as Claude Code or Codex solves by driving a simulated robot from its shell with the `robo` command, and "An episode server runs the simulator, enforces the step budget, records a video and scores the final physical state", so the agent never grades itself. "robouse 0.6.0 bundles 790 tasks in 34 suites" (LIBERO, LIBERO-PRO, robosuite, Meta-World, ManiSkill3, RoboCasa, MyoSuite, dm_control and more); VLA baselines run behind the same server, and trial pages are public at [robouse.ai/runs](https://robouse.ai/runs/). 0.5.0 added a harness for Dream Labs' Dream-1 (§3a); 0.6.0 adds harnesses for NVIDIA's ASPIRE workflow (§1c), Kinex (§1a), TypeSafe's Jev (§2a) and Gemini CLI. Apache-2.0. 🆕 ⚠️ Built by BenchFlow, which maintains this list.
- **[Kinex](https://stacx-lab.github.io/kinex/)** — Georgia Tech and Harvard contributors — <https://stacx-lab.github.io/kinex/> · code <https://github.com/stacx-lab/kinex> · *harness, v1.0.0 2026-10-15* — "A general harness that connects coding agents to any physical robot", built on the Pi coding-agent SDK with three layers (devices, tools, skills) and ROS 2 support. Evaluated zero-shot on 132 LIBERO, RoboTwin and RoboDojo tasks with each suite's native success criteria: "Kinex raises success from 72.7% to 78.0% at 42.9% lower cost than Codex + Bare action API." Episodes and agent traces are on Hugging Face (§7). Robo Use (§1a) added a harness for it in 0.6.0. Apache-2.0. 🆕 ⚠️ Released 2026-10-15, so few outside users yet; results are the authors' own.
- **[DimOS](https://github.com/dimensionalOS/dimos)** — Dimensional — <https://github.com/dimensionalOS/dimos> · evals docs <https://docs.dimensional.org/usage/evals/> · *robot OS, 2024-10-19* — "The Agentive Operating System for Physical Space": a Python robot OS (no ROS required) for quadrupeds, humanoids, arms and drones whose skills agents reach through a CLI and an MCP server; "The dimos CLI manages the full lifecycle — run blueprints, inspect state, interact with agents, and call skills via MCP." It ships its own agent-evaluation harness, `dimos evals`, and powers Can Jev Nav? (§4a). Apache-2.0. 🆕 ⚠️ "Pre-Release Beta".
- **[Inspect Robots](https://github.com/robocurve/inspect-robots)** — Robocurve — <https://github.com/robocurve/inspect-robots> · paper <https://arxiv.org/abs/2610.06306> · docs <https://docs.inspectrobots.org/> · *eval harness, paper 2026-10-05* — "Evaluating the Capabilities and Safety of Embodied AI": an Inspect-style framework where any policy, an LLM agent or a VLA, runs on real arms or humanoids (YAM, Franka, SO-101, G1 and others) or in simulators, with logged transcripts and grader scores; StationeryBench and RoboHarm are built on it. "Inspect Robots has seen significant early uptake, receiving nearly 100,000 downloads in the three months since its release." MIT. 🆕 ⚠️ Alpha; the download count is the authors' own.
- **[RPent](https://github.com/RLinf/RPent)** — RLinf; paper from Tsinghua University and others — <https://github.com/RLinf/RPent> · paper <https://arxiv.org/abs/2607.08448> · *harness, paper 2026-07-09* — "Agentic Infrastructure for the Physical World": Claude Code, Codex or an API model plans, and frozen VLAs such as π0.5 become retryable primitives guided by memory (the paper calls it Harness VLA). Its leaderboard covers LIBERO, LIBERO-PRO, RoboCasa365 and RoboTwin; with Codex and GPT-6 Astra it reports "92.63% Overall (741/800) across all eight LIBERO-PRO suites". Apache-2.0. 🆕 ⚠️ Leaderboard results are self-reported.
- **[PyRUA-Lean](https://github.com/DAGroup-PKU/PyRUA-Lean)** — Peking University, NUS, NVIDIA and others — <https://github.com/DAGroup-PKU/PyRUA-Lean> · paper <https://arxiv.org/abs/2610.01939> · *harness, paper 2026-10-01* — The robot is a Python object, `robo`, and the agent works through one `python(code)` tool that composes primitives (VLAs included) instead of making one tool call per action; "it raises success from 63.1% to 71.7% over tool calling with the same GPT-6 Astra planner and primitives". Apache-2.0. 🆕 ⚠️ Simulation only so far.
- **[Show-Harness](https://github.com/showlab/Show-Harness)** — NUS Show Lab — <https://github.com/showlab/Show-Harness> · paper <https://arxiv.org/abs/2609.10522> · *harness, paper 2026-09-09* — "Just a VLM Agent Can Play Robots": VLMs reason over discrete semantic action units that per-robot interpreters turn into motion, so frontier VLMs run zero-shot and small open VLMs can be adapted "with just a few GPU-hours of fine-tuning"; LoRA adapters and data are released. Apache-2.0. 🆕
- **[RoboHarness](https://github.com/BinceQu/RoboHarness)** — Zhejiang University — <https://github.com/BinceQu/RoboHarness> · paper <https://arxiv.org/abs/2610.14018> · *harness, paper 2026-09-29* — A visual-geometric control panel for an LLM agent (clicked keypoints, optical-flow tracking, depth back-projection, geometric constraints), with Claude Code and Codex harnesses for BEHAVIOR Challenge 2025 tasks: "With RoboHarness, Qwen3.8-Flash-Next outperforms state-of-the-art VLA models on BEHAVIOR Challenge 2025 tasks." MIT. 🆕 ⚠️ BEHAVIOR data needs its own non-commercial licence (§4b).
- **[RobotUse](https://github.com/robotuse-team/RobotUse)** — KAIST and Seoul National University — <https://github.com/robotuse-team/RobotUse> · paper <https://arxiv.org/abs/2610.04929> · *harness, paper 2026-10-04* — Splits the work: the agent picks targets and poses visually while the backend handles geometry, motion planning and control, with subagents per subgoal and a persistent playbook of lessons; "On RoboLab, RobotUse achieves 45% task success, outperforming CaP-X by 6.7 percentage points". Apache-2.0. 🆕 ⚠️ The released code runs only in RoboLab (Isaac Sim); real-robot results are in the paper only.
- **[OpenRUA](https://github.com/terminalworld/OpenRUA)** — UCL and CMU — <https://github.com/terminalworld/OpenRUA> · paper <https://arxiv.org/abs/2610.02459> · *harness, paper 2026-10-01* — "Robot-Use Agents Are Zero-Shot Visuomotor Policies": an off-the-shelf Claude Code or Codex gets only terminal access to the robot's native ROS 2 interface and its documentation, with no custom primitives and no VLA; "With Claude Code powered by Claude Opus 5, OpenRUA achieves success rates of 99.0% on CaP-Bench and 87.0% on LIBERO-PRO". Apache-2.0. 🆕 ⚠️ Simulated benchmarks; few outside users yet.
- **[PhyAgentOS](https://github.com/PhyAgentOS/PhyAgentOS-core)** — Sun Yat-sen University, Peng Cheng Laboratory, X-Era Lab — <https://github.com/PhyAgentOS/PhyAgentOS-core> · paper <https://arxiv.org/abs/2607.16636> · *robot agent OS, paper 2026-07-18* — A self-evolving operating system for embodied agents that separates cognitive planning from physical execution, passes state between agent and runtime as files, and adds a session verifier, memory of past runs, layered safety and robot integrations packaged as skills; "validated on 19+ simulated and physical embodiments". MIT. 🆕
- **[ROSClaw](https://github.com/ros-claw/rosclaw)** — Tongji University and SRIAS — <https://github.com/ros-claw/rosclaw> · *runtime, 2026-03-16* — A governed runtime between agents (Codex, Claude Code, OpenClaw, VLAs) and bodies (ROS 2, MCP, simulators, vendor SDKs) that checks policy and authorisation before each action and writes an execution receipt for it. MIT. 🆕 ⚠️ "ROSClaw is alpha software"; its maturity table marks real hardware as experimental.
- **[Strands Robots](https://github.com/strands-labs/robots)** — AWS Strands Labs — <https://github.com/strands-labs/robots> · *agent tools, v0.5.3 2026-10-07* — "Control, simulate, and train robots with natural language": a `Robot()` tool for Strands Agents that returns a MuJoCo simulation or a real robot and runs LeRobot, GR00T and Cosmos policies. Apache-2.0. 🆕 ⚠️ Strands Labs is AWS's organisation for experimental projects.
- **[AgenticROS](https://github.com/agenticros/agenticros)** — AgenticROS project — <https://github.com/agenticros/agenticros> · *MCP server + plugin, 2026-03-01* — An agent-agnostic layer for ROS 2 robots: an OpenClaw plugin and one MCP server for Claude Code, Codex CLI, Hermes, Antigravity and Gemini CLI. NVIDIA's [Isaac ROS 5.0 post](https://blogs.nvidia.com/blog/isaac-ros-5-0-agentic-open-source-robotics/) (2026-09-22) points to it: "AgenticROS, an open source project sponsored by 3D perception technology company RealSense, connects Isaac ROS". Apache-2.0. 🆕
- **[RAI](https://github.com/RobotecAI/rai)** — Robotec.ai — <https://github.com/RobotecAI/rai> · paper <https://arxiv.org/abs/2505.07532> · *agent framework, paper 2025-05-12* — A vendor-agnostic multi-agent framework on ROS 2 with speech, simulation and its own benchmark: "rai_bench: Benchmarking suite for RAI. Test agents, models, tools, simulators, etc." Apache-2.0. 🆕
- **[NVIDIA Agent Skills](https://github.com/NVIDIA/skills)** — NVIDIA — <https://github.com/NVIDIA/skills> · Isaac Lab skills <https://isaac-sim.github.io/IsaacLab/v3.0.0-EA/source/developer-tools/agent_skills.html> · *skills, 2026-02-25* — Signed skills that teach coding agents robotics, simulation and CUDA work, each published skill carrying its own evaluation set; Isaac Lab 3.0 ships 17 user-facing skills, and "User-facing skills must also include an evaluations.md file with at least three representative scenarios." Apache-2.0 and CC BY 4.0. 🆕

### 1b · MCP servers and device standards

- **[Model Hardware Standard](https://www.anthropic.com/news/model-hardware-standard-research-preview)** — Anthropic, with HHMI Janelia — <https://www.anthropic.com/news/model-hardware-standard-research-preview> · *standard preview, 2026-08-27* — "a shared specification for AI agents to safely operate physical devices": standard device drivers with discovery and read/write primitives, model-agnostic and reachable over MCP, for microscopes, liquid handlers and robot arms. 🆕 ⚠️ Gated research preview with an application form; the spec is not public, and the post describes the preview as coming "ahead of making the standard open source".
- **[Qwen-MM-Plugins](https://github.com/QwenLM/Qwen-MM-Plugins)** — Qwen — <https://github.com/QwenLM/Qwen-MM-Plugins> · *plugins, MHS host added 2026-09-20* — Plugins that make agent harnesses (Claude Code, Codex, Qwen Code, OpenClaw) multimodal; its `mhs` plugin is an open MHS host with a fixed six-tool surface, host-side safety limits and an emergency stop, and "Operates real hardware — cameras, sensors, lamps, arms, lab equipment — through Model Hardware Standard adapters". Apache-2.0. 🆕 ⚠️ Device adapters come from hardware owners under the gated MHS preview.
- **[ROS MCP Server](https://github.com/robotmcp/ros-mcp-server)** — Robot MCP — <https://github.com/robotmcp/ros-mcp-server> · *MCP server, v3.1.2 2026-09-23* — "ROS-MCP-Server connects large language models (such as Claude, GPT, and Gemini) to robots": any MCP client reaches topics, services, actions and parameters on ROS 1 or ROS 2 robots through rosbridge. Apache-2.0. 🆕 ⚠️ Needs rosbridge; no evaluation of its own.

### 1c · Agents that write and improve robot code and skills

- **[Code as Policies](https://arxiv.org/abs/2209.07753)** — Liang et al. (Google) — <https://arxiv.org/abs/2209.07753> · *paper, 2022-09-16* — "Language Model Programs for Embodied Control": code-writing LLMs, prompted with a few examples, write robot policy code that processes perception outputs and parameterises control primitives. The idea behind CaP-X (§4a) and most harnesses above.
- **[VoxPoser](https://arxiv.org/abs/2307.05973)** — Huang et al. (Stanford) — <https://arxiv.org/abs/2307.05973> · *paper, 2023-07-12* — LLMs compose 3D value maps that a motion planner turns into dense 6-DoF end-effector trajectories, for open-set instructions and objects without predefined motion primitives.
- **[ASPIRE](https://research.nvidia.com/labs/gear/aspire/)** — NVIDIA GEAR with UMich, UIUC, UC Berkeley, CMU — <https://research.nvidia.com/labs/gear/aspire/> · paper <https://arxiv.org/abs/2607.00272> · code <https://github.com/NVlabs/ASPIRE> · *paper + code, 2026-06-30* — Agentic skill discovery: a coding agent writes and refines control programs from multimodal execution traces, saves verified fixes to a growing skill library, and uses evolutionary search over tasks and programs; ASPIRE "is a new type of continual learning" in which training means refining skills rather than gradient descent. "On 10 LIBERO-Pro tasks, success rises from 15% (GPT-6 Luna) to 99% (Claude Opus 5.5)"; it also reports robosuite and BEHAVIOR-1K results and early sim-to-real transfer. Robo Use (§1a) added a harness for its workflow in 0.6.0. Apache-2.0. 🆕 ⚠️ The authors "have not verified that smaller or weaker LLMs can sustain the debugging loop".
- **[ENPIRE](https://research.nvidia.com/labs/gear/enpire/)** — NVIDIA, CMU, UC Berkeley — <https://research.nvidia.com/labs/gear/enpire/> · paper <https://arxiv.org/abs/2606.19980> · code <https://github.com/NVlabs/ENPIRE> · *paper + code, 2026-06-18* — "Agentic Robot Policy Self-Improvement in the Real World": a coding-agent harness that resets and verifies the environment, improves the policy, runs rollouts on one or several robots and evolves its approach, to "autonomously train a policy to achieve a 99% success rate on challenging, dexterous manipulation tasks" (CoRL 2026). Apache-2.0. 🆕 ⚠️ Real-robot use needs a calibrated station.
- **[SimEX](https://robo-simex.github.io/)** — Amazon FAR, UT Austin, CMU — <https://robo-simex.github.io/> · paper <https://arxiv.org/abs/2609.38982> · *paper, 2026-09-30* — "Simulation-Integrated Robotics AutoResearch": a coding agent builds a robot toolbox through probe-and-optimise cycles in simulation, then adapts toolbox and simulator together from a few real trials, "without any demonstration and with only 10 minutes of real-robot interaction". 🆕 ⚠️ No code released.
- **[SEAR](https://sear.bot/)** — Luma AI — <https://sear.bot/> · paper <https://arxiv.org/abs/2610.18792> · *paper + benchmark, 2026-10-13* — "Self-Evolving Agentic Robotics": agents act as the policy, write the code, or fine-tune a VLA, with controls that separate retained experience from retries, luck and privileged simulator state, "Across seven frontier language models, 330 simulated and five physical tasks". 🆕 ⚠️ Code "coming soon": the repository holds only a README.

## 2 · Robot reasoning models and VLAs

### 2a · Embodied reasoning and frontier models for robots

- **[SayCan](https://arxiv.org/abs/2204.01691)** — Ahn et al. (Google) — <https://arxiv.org/abs/2204.01691> · *paper, 2022-04-04* — "Do As I Can, Not As I Say: Grounding Language in Robotic Affordances": an LLM proposes steps and the value functions of pretrained skills ground them in what the robot can do in its current state.
- **[Gemini 4 Argon for Robotics](https://developers.googleblog.com/gemini-4-argon-for-robotics/)** — Google (Kanishka Rao) — <https://developers.googleblog.com/gemini-4-argon-for-robotics/> · *blog + API, 2026-10-13* — Google's frontier model as a robot agent. On ERQA, "Using pure reasoning, Argon scores 87%, outperforming every other frontier model"; it improves an SO-101 pick-and-place over three iterations (58.9 s, 22.9 s, 17.4 s), and from a single RGB photo builds a calibrated MuJoCo twin, defines a 77-task curriculum and exports 4,500+ episodes to fine-tune a VLA, "boosting real-world physical robot Success Rate from 56% to 75%". Paid Gemini API tier (`gemini-4-argon`) and Antigravity. 🆕 ⚠️ Self-reported; the harness and tasks are not released.
- **[Gemini Robotics-ER 2](https://deepmind.google/models/gemini-robotics/embodied-reasoning/)** — Google DeepMind — <https://deepmind.google/models/gemini-robotics/embodied-reasoning/> · docs <https://ai.google.dev/gemini-api/docs/robotics-overview> · *model + API, 2026-07-30* — An embodied-reasoning model for spatial reasoning, planning and multi-robot orchestration through function calling; "It then hands off motor execution to any given lower level vision-language-action (VLA) model." Public preview in the Gemini API (`gemini-robotics-er-2-preview`). 🆕 ⚠️ Closed model; benchmark numbers on the page are self-reported.
- **[Glimpse](https://elorian.ai/blog/introducing-glimpse)** — Elorian — <https://elorian.ai/blog/introducing-glimpse> · *model + API, 2026-10-16* — "a new category of visual thinking model: a system that reasons about the physical world from what it sees", trained to call multimodal tools and coordinate subagents; robotics is one target: one demo labels a robot episode and "splits the episode into six pick-and-place events", another plans and checks the work of a VLA. "Glimpse is available through API and our chat UI today": "Input tokens cost $0.60 per million and output tokens $3.00 per million". 🆕 ⚠️ Benchmarks are self-reported; no weights (it was "post-trained on an open weights base model").
- **[Jev](https://docs.typesafe.ai/introduction)** — TypeSafe — <https://docs.typesafe.ai/introduction> · *model + docs, undated* — "TypeSafe's flagship model and the first System One model": instead of generating text, it answers typed questions (Choice, Score, Noul) about a state with structured values that code can act on directly. Can Jev Nav? (§4a) tests it as a real-time navigation policy, and Robo Use (§1a) added a harness for it in 0.6.0. 🆕 ⚠️ The docs give no date, access route or pricing.
- **[UnifoLM-ER-1](https://huggingface.co/unitreerobotics/UnifoLM-ER-1)** — Unitree — <https://huggingface.co/unitreerobotics/UnifoLM-ER-1> · *open model, 2026-09-11* — An open 4B embodied-reasoning VLM built on Qwen3-VL-4B, released with Unitree's whole-body humanoid model [UnifoLM-WLA-1.0](https://github.com/unitreerobotics/unifolm-wla), a "next-generation general-purpose humanoid robot foundation model with 6B parameters". Apache-2.0, ungated. 🆕

### 2b · Vision-language-action models and learned policies

- **[RT-2](https://arxiv.org/abs/2307.15818)** — Brohan et al. (Google DeepMind) — <https://arxiv.org/abs/2307.15818> · *paper, 2023-07-28* — "Vision-Language-Action Models Transfer Web Knowledge to Robotic Control": co-fine-tunes a web-scale vision-language model on robot trajectories and web tasks so one model maps robot observations to actions and carries over semantic reasoning from web data.

NVIDIA presents it as "an industrial-strength data engine used for training GR00T models", "roughly ~125× cheaper than GPT-6 Astra" and "labeling 200,000 hours of data per day across 512 GB300s"; on RoboReward its MAE is 40.0 against GPT-6 Astra's 55.4, while Astra leads on the Robot200 captioning subset and on RubricBench. 🆕 ⚠️ Weights and inference scripts are under the NVIDIA OneWay Noncommercial License, and "Flora is not intended or supported for commercial or production use".
- **[S4VY](https://arxiv.org/abs/2609.36875)** — Jingdong Zhang, Xin Li, Jan Kautz, Wenping Wang, Chris Choy — <https://arxiv.org/abs/2609.36875> · code <https://github.com/Evergreen0929/S4VY> · *paper, 2026-09-29* — "We introduce S4VY, a Segment Anything model built on feed-forward 4D visual geometry": class-agnostic 4D instance masks that track each object across all frames from RGB, prompt-free or point- and box-prompted, plus an agentic system for natural-language grounding in 4D scenes. 🆕 ⚠️ Code "Coming soon": "The code is pending release approval and will be published in this repository."
- **[SAM 3](https://github.com/facebookresearch/sam3)** — Meta — <https://github.com/facebookresearch/sam3> · paper <https://arxiv.org/abs/2511.16719> · *model, 2025-11-20* — Segments and tracks every instance of a concept given as text or an example, in images and video; "It achieves 75-80% of human performance on our new SA-CO benchmark which contains 270K unique concepts". CaP-X uses it as a perception primitive. 🆕 ⚠️ A custom SAM licence with trade-control and ITAR restrictions; the weights are gated.
- **[Grounded SAM 2](https://github.com/IDEA-Research/Grounded-SAM-2)** — IDEA Research — <https://github.com/IDEA-Research/Grounded-SAM-2> · *pipeline, v1.0 2024-12-11* — "Grounded SAM 2 is a foundation model pipeline towards grounding and track anything in Videos": open-vocabulary detection (Grounding DINO, Florence-2 or DINO-X) plus SAM 2 for text-prompted segmentation and tracking. Apache-2.0. ⚠️ The newer DINO-X detectors are available only through a cloud API.
- **[FoundationPose](https://github.com/NVlabs/FoundationPose)** — NVIDIA — <https://github.com/NVlabs/FoundationPose> · *model, 2023-12-13* — 6D pose estimation and tracking of novel objects, with or without a CAD model (CVPR 2024). ⚠️ Non-commercial [licence](https://github.com/NVlabs/FoundationPose/blob/main/LICENSE): "The Work and any derivative works thereof only may be used or intended for use non-commercially."
- **[GraspGen](https://github.com/NVlabs/GraspGen)** — NVIDIA — <https://github.com/NVlabs/GraspGen> · paper <https://arxiv.org/abs/2507.13097> · *model, 2025-07-17* — A diffusion model that generates 6-DoF grasps for parallel-jaw and suction grippers, served over ZMQ and callable by agents: "Added MCP for calling GraspGen as a tool by an LLM." Dataset CC BY 4.0. 🆕 ⚠️ The code is under a non-commercial NVIDIA licence.
- **[VGGT](https://github.com/facebookresearch/vggt)** — Meta (Wang, Karaev, Vedaldi, Rupprecht, Novotny et al.) — <https://github.com/facebookresearch/vggt> · paper <https://arxiv.org/abs/2503.11651> · *model, 2025-03-14* — Feed-forward prediction of cameras, depth, point maps and tracks from one to hundreds of views (CVPR 2025 Best Paper). 🆕 ⚠️ "We've updated the license for VGGT to permit commercial use (excluding military applications)."; the original VGGT-1B weights stay CC BY-NC 4.0, and the commercial checkpoint is gated.
- **[Depth Anything 3](https://github.com/ByteDance-Seed/Depth-Anything-3)** — ByteDance Seed — <https://github.com/ByteDance-Seed/Depth-Anything-3> · paper <https://arxiv.org/abs/2511.10647> · *model, 2025-11-13* — Depth and camera-ray estimation from any number of views, plus metric and monocular depth and a streaming mode for long video. Code Apache-2.0. 🆕 ⚠️ The largest weights are CC BY-NC 4.0; smaller ones are Apache-2.0.
- **[CoTracker3](https://github.com/facebookresearch/co-tracker)** — Meta — <https://github.com/facebookresearch/co-tracker> · paper <https://arxiv.org/abs/2410.11831> · *model, 2024-10-15* — Tracks any pixel through a video, offline or online, trained by pseudo-labelling real videos. ⚠️ "The majority of CoTracker is licensed under CC-BY-NC".
- **[Molmo 2](https://allenai.org/blog/molmo2)** — Ai2 — <https://allenai.org/blog/molmo2> · code <https://github.com/allenai/molmo2> · ER model <https://huggingface.co/allenai/Molmo2-ER> · *models, 2025-12-11* — Open vision-language models for video QA, pointing with coordinates and timestamps, and tracking; Molmo2-ER is the embodied-reasoning backbone of MolmoAct 2 (§2b). Apache-2.0. 🆕 ⚠️ Trained partly on third-party data "subject to academic and non-commercial research use only".
- **[Rerun](https://github.com/rerun-io/rerun)** — Rerun — <https://github.com/rerun-io/rerun> · *tool, 0.39.0 2026-10-12* — "Log, query, visualize, and stream to training on shared columnar storage built for multimodal data": the open viewer for robot logs, reading MCAP and LeRobot data. MIT and Apache-2.0. 🆕
- **[Foxglove](https://foxglove.dev/blog/foxglove-goes-agentic)** — Foxglove — <https://foxglove.dev/blog/foxglove-goes-agentic> · *tool, 2026-08-18* — Robot-data visualisation with an in-app agent and a local MCP server over recordings (layouts, scripts, semantic search). 🆕 ⚠️ Proprietary; "Agentic workflows are available in beta to all customers."
